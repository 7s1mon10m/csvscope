# csvscope

把一个 CSV 拖进去，立刻看到它里面到底有什么：每列是什么类型、缺了多少、
取值怎么分布、哪些是异常值、哪几列强相关。

**零第三方依赖。零安装。数据一步都没离开这台机器。**

```bash
python csvscope.py data.csv
```

就这一条。不需要 `pip install`，不需要 `npm`，不需要 Docker，不需要注册账号。

## 为什么是它，而不是别的

**1. 你的数据不出本机。** 列类型、缺失率、分布、异常值、相关性——这些活
现在要么自己写 pandas 代码，要么把文件传到某个在线工具上。第二件事很多人
**根本不能做**。csvscope 起的是一个只监听 `127.0.0.1` 的本地网页服务，
关掉进程什么都不剩，不落盘、不留档、不联网。

**2. 原始数据不进浏览器。** 前端拿到的只是**统计摘要**（直方图分桶、top 值、
缺失率），几 KB 而已。所以一百万行的文件不会把浏览器卡死，你也不必有
「我的数据被塞进了一个网页里」的顾虑。想看某列具体长什么样，得自己点
「查看样本」，后端才按需读前 20 行出来。

**3. 纯标准库。** 后端是 `http.server`，前端是不打包的原生 HTML/CSS/JS，
统计全用 Python 标准库手写。同类工具基本都拖着 pandas 这个巨型依赖，
而 csvscope 克隆下来就能跑。

## 试试看

```bash
python csvscope.py examples/demo.csv
```

`examples/demo.csv` 是故意做脏的：带 BOM 的编码、重复列名、前导零的邮编、
`$1,234.56` 这样的金额、`(88.00)` 这样的会计负数、`50%`、`N/A` 和 `null`、
引号里的逗号和换行。项目里的大部分处理逻辑都能在这一个文件上看到效果。

不想开浏览器：

```bash
python csvscope.py examples/demo.csv --no-serve
```

### 参数

| 参数 | 作用 |
|---|---|
| `--port N` | 监听端口（默认 8765，被占用时自动换一个） |
| `--no-browser` | 不自动打开浏览器 |
| `--no-serve` | 只扫一遍，把报告打到控制台，不启动网页服务 |
| `--encoding X` | 手动指定编码（默认自动嗅探） |
| `--delimiter X` | 手动指定分隔符（默认自动嗅探） |
| `--dump-json P` | 把完整报告写成 JSON |

## 它看得懂什么

| 列的情况 | 它会怎么处理 |
|---|---|
| UTF-8 / **带 BOM** / GBK / CP1252 | 自动嗅探并剥离 BOM |
| 逗号 / 制表符 / 分号 / 竖线 | 自动嗅探，并列出各候选的评分 |
| `$1,234.56`、`(1,234)`、`50%`、`1.2e5` | 认得出，**并在报告里写明做了处理** |
| `N/A` / `NaN` / `null` / 空串 | 按缺失统计 |
| 订单号、电话、邮编这类「数字」 | 判为**编号**，不算均值 |
| 列数不齐的行 | 按缺失处理，并报告有哪几行不齐 |
| 引号里的逗号、换行、转义双引号 | 正确还原 |
| 同名列、空列名 | 自动去重 / 补名 |

## 它**不**做什么

- **不改你的文件。** 只读。没有删除、没有清洗、没有导出覆盖。
- **不读 Excel。** `xlsx` 需要第三方库。范围就划在 CSV / TSV。
- **不落盘、不留历史。** 关掉进程什么都不剩。
- **不联网。** 一个字都不往外发。

## 三处我觉得值得说清楚的实现

### 1. 均值用 Welford 算，不用 `sum(x²)`

在线计算方差有个流传很广的写法：`sum(x²) - sum(x)²/n`。它在数值大、
方差小的时候会**彻底失效，而且不报错**。实测：

```
值 = 1e9 附近的四个数，真实方差 30
朴素公式给出：0.0
```

不是"精度差一点"，是比答案本身还大的量级。Welford 是同样几行代码但正确的
写法（`m2 += delta * (x - mean_new)`——注意用的是**更新后**的均值，
写错成同一个均值两次结果会慢慢漂）。见 `profile.py::ColumnStats._add_number`。

### 2. 直方图和相关性用蓄水池抽样

均值、标准差、最小/最大是**全量精确**的，跟文件多大无关。但直方图需要先知道
取值范围，相关性需要同一行的多个列对齐——都不可能在单遍流式里精确算出来。

所以留了一个 **行级蓄水池抽样**（Algorithm R）：小文件全量留下（等于没抽样），
大文件等概率保留 4000 行。报告里会**明确写出哪些数是精确的、哪些是抽样的**，
而不是把两者混在一起说成"结果"。

容易写错的地方：取样必须用 `random.randrange(seen)`，写成 `random.randrange(k)`
会让前面的行永远被压住——且结果看起来"也挺随机"。`tests/test_profile.py`
里有一条测试专门盯这件事。

### 3. 看起来像数字，不等于能算平均值

`010010` 是邮编，`20260815001` 是订单号。它们全是数字，但给它们算均值是
胡说——"平均订单号 30512"不是结论，是错误。

csvscope 会识别前导零、以及"位数多 + 几乎不重复"的整数，判为**编号**，
并**把均值从数据里整个抹掉**（不是"界面上不显示"——值还在的话，早晚有人
拿它去画图）。

### 顺带一提：两个不太好找的坑

- **`http.server.HTTPServer` 是单线程的。** 扫描线程一跑，页面请求全被堵死，
  浏览器永远白屏。必须用 `ThreadingHTTPServer`，再加 SSE 把进度推出去。
- **`csv.reader` 只能用同一个实例读同一个行流。** 如果按行切开、每行新建一个
  reader（`next(csv.reader([line]))`），引号里带换行的字段会被**切碎且不报错**。
  地址、备注、JSON 字段上极容易踩到。

## 文件结构

```
csvscope/
├── csvscope.py     入口：HTTP 服务、SSE 进度、API、控制台摘要
├── reader.py       编码/分隔符嗅探 + 流式逐行读取
├── profile.py      流式统计：Welford、蓄水池抽样、类型推断、相关性
├── static/         报告界面（原生 HTML/CSS/JS，无构建步骤）
├── tests/          标准库 unittest，89 条
└── examples/       故意做脏的演示 CSV
```

## 测试

零依赖，不需要装 pytest：

```bash
python -m unittest discover -s tests
```

覆盖的都是真实世界的脏数据：BOM、GBK、分号分隔、引号里的换行、列数不齐、
超长字段、千分位、前导零、日期、唯一值上限、抽样公平性、成对删除的相关性。
每一条都对应一个踩过的坑，不是为覆盖率写的。

## 已知的局限（都是有意为之的取舍）

- **类型推断看的是前 200 行**。一列如果前 200 行全是文本、后面才变成数字，
  它会被当作文本列。
- **超过 4000 行的文件，直方图和相关性是抽样的**（报告里会写明）。
- **唯一值统计上限 10000**。超过就停止收录新值并标注截断。
- **「查看样本」会重读文件**，且最多扫前 20 万行。
- 单个文件、单次会话，没有多文件对比。
